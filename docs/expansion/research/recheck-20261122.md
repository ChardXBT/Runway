## 1. YouTube

| Fact | Evidence | Spec change |
| --- | --- | --- |
| The 2 November 2026 entry is confirmed verbatim: uploads "from unverified API projects are no longer restricted to private viewing mode", reversing the 28 July 2020 policy. An omitted `privacyStatus` "defaults to public"; "certain uploads might default to private based on creator account settings". | [Official] [revision history](https://developers.google.com/youtube/v3/revision_history), read 2026-11-22 | None (already invariant 13). Test Y-3 still required. |
| **New, 16 November 2026: a `posts` resource** ("represents a YouTube post"), i.e. a Community-post API. Methods `list`, `insert`, `update` (text only), `delete`, and `imageUpload` (`POST https://www.googleapis.com/upload/youtube/v3/posts/image?channelId=…`, JPEG/PNG/GIF/WebP, ≤ 16 MB, aspect 2:5 to 5:2, returns `imageUploadToken`). `posts.insert` takes `snippet.channelId`, `snippet.textDisplay` and 1–10 `attachments.imageAttachments[].uploadToken`; "Scheduled posts aren't supported"; it publishes immediately; 1 unit against a separate "Post Uploads" quota. Scopes: `youtube`, `youtube.force-ssl` or `youtubepartner` (imageUpload also accepts `youtube.upload`). **Pilot only**: "available only to select launch partners (approved Google Cloud projects), with broader public API access planned for General Availability in 2027." | [Official] [posts](https://developers.google.com/youtube/v3/docs/posts), [posts.insert](https://developers.google.com/youtube/v3/docs/posts/insert), [posts.imageUpload](https://developers.google.com/youtube/v3/docs/posts/imageUpload), read 2026-11-22 | Spec 08 §2 gains a `youtube_post` adapter for Community posts, built against mocks and gated by `youtube_posts_api_access` (off). When on, an accepted Lineup proposal can go out by API instead of the browser publisher. Scheduling is `held` only. The browser publisher stays the default. |
| 16 November 2026: `paidProductPlacementDetails.hasPaidProductPlacement` "no longer defaults to false"; omitted means "the video isn't declared as free of paid product placement". | [Official] revision history | Spec 08 §2: `has_paid_product_placement` becomes a required boolean in YouTube target settings, like `made_for_kids`. No default. |
| 15 October 2026: `selfDeclaredMadeForKids` / `madeForKids` are only updated when specified. | [Official] revision history | None; Runway always sends it. |
| 3 November 2026: `thumbnails.set` accepts custom Shorts thumbnails after processing. | [Official] revision history | None (spec already calls `thumbnails.set` after processing). |
| Google OAuth: "Testing" status gets refresh tokens "expiring in 7 days"; 100 refresh tokens per Google account per client, oldest silently invalidated; 6 months unused; time-based access. The page says nothing about unverified apps "In production". | [Official] [OAuth 2.0 overview](https://developers.google.com/identity/protocols/oauth2), read 2026-11-22 | None. U6 stays open; test Y-1 settles it. |
| WebSub: Google's hub grants leases of about 5 days (432,000 s) whatever is requested, and notifications stop silently when it lapses. With `hub.secret`, the hub signs the raw body with HMAC-SHA1 in `X-Hub-Signature: sha1=<hex>`. A debug page shows lease state. | [Community] several implementers; [Official] PubSubHubbub 0.4 for the signature format | Spec 04 §2: renew at 80% of the granted lease. Verify `sha1=` (and accept `sha256=` if present). Use the hub's `subscription-details` page in the runbook for debugging. |

## 2. Instagram

| Fact | Evidence | Spec change |
| --- | --- | --- |
| The publishing page still says both "100 API-published posts within a 24-hour moving period" (carousels count as one) and, in the carousel section, "50 published posts within a 24-hour period". | [Official] [content publishing](https://developers.facebook.com/docs/instagram-platform/content-publishing), read 2026-11-22 | None. Keep 50 until `content_publishing_limit` says otherwise. |
| Resumable upload (`upload_type=resumable`, `rupload.facebook.com`) is documented "only for apps that have implemented Facebook Login for Business". The Instagram Login column lists only `graph.instagram.com`. So the owner's current Instagram Login path still needs a public media URL. | [Official] same page | None. Spec 02's signed URL stays. "Unified Login" as a name was not found in this pass; the newer path to watch is Facebook Login for Business, which has resumable upload from disk. Spec 08 §3 renamed accordingly. |
| Long-lived Instagram Login tokens last 60 days. Refresh with `grant_type=ig_refresh_token` once the token is at least 24 hours old and unexpired. Tokens not refreshed within 60 days cannot be refreshed. | [Official] [business login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login) | Spec 04 §3: schedule a `refresh_token` job for Instagram at about 50 days and never before 24 hours. Warn the user at 14 days left, as for other platforms. |
| `is_ai_generated` works for both login types; on a carousel, set it on the parent only ("Setting this parameter on carousel children will result in an error"). `alt_text` exists for image posts only, not Reels or Stories. Trial reels: `trial_params.graduation_strategy` = `MANUAL` or `SS_PERFORMANCE`. | [Official] same page | Spec 08 §3 target settings updated: no `is_ai_generated` on children, no `alt_text` on Reels or Stories. |
| **Error 9007, subcode 2207027, "Media ID is not available"** on `media_publish`, often seconds after the container reports `FINISHED`. Many schedulers hit it in 2025–2026. The working fix is to retry `media_publish` **with the same `creation_id`**, only for this error, for about 1–2 minutes. A container can be published only once, so reusing it cannot duplicate a post. | [Community] Make.com forum thread; PRs in several open-source schedulers (e.g. kaanmuar #3005, ehlersio/eyewall-pipeline #235, Bigtimedee/PackPoints-Game #332) | Spec 08 §3 "Send": on 9007/2207027, read the container. If `PUBLISHED`, find the media id; else retry `media_publish` with the same `creation_id` every 10 s for up to 2 minutes, then `uncertain`. Never create a second container for a target whose container may have been published. |
| Business Verification is required for Advanced Access to accounts that have no role on the app. Individual verification was discontinued in 2023. In practice a formally registered sole proprietorship (or equivalent) with matching documents can pass; a purely personal developer cannot. Meta caps a developer at 15 apps not connected to a verified business. | [Official] Meta blog 2023-02-01 and access-levels page; [Community] 2026 guides | OPEN-QUESTIONS U4 answered as far as documents allow. Q5 (register a business?) is now the real gate for hosted Instagram. |

## 3. TikTok

| Fact | Evidence | Spec change |
| --- | --- | --- |
| Content Sharing Guidelines (last updated 4 August 2026) still list as not acceptable "A utility tool to help upload contents to the account(s) you or your team manages" and apps for "internal groups/private use". Mandatory screen rules unchanged. | [Official] [guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines) | None. |
| Inbox upload: `POST /v2/post/publish/inbox/video/init/`, scope `video.upload`, "at most 5 pending shares within any 24-hour period" (403 `spam_risk_too_many_pending_share`), 6 requests per minute per user token, upload URL valid one hour, user finishes in the app from an inbox notification. The official pages say nothing about audit or sandbox for this path. | [Official] [upload reference](https://developers.tiktok.com/doc/content-posting-api-reference-upload-video), [get started](https://developers.tiktok.com/doc/content-posting-api-get-started-upload-content) | Spec 08 §4: 6/min per token added to the rate guard. |
| Several independent vendors and open-source projects report that inbox upload works for **unaudited** apps and is exempt from the private-account rule; one vendor says it also works in sandbox. | [Community] | U2 is now likely, not proven. Test T-2 still decides it. |
| Chunk rules confirmed: each chunk 5–64 MB except the last, which may be up to 128 MB; `total_chunk_count = floor(video_size / chunk_size)`; files under 5 MB go whole; video ≤ 4 GB; images ≤ 20 MB. | [Official] [media transfer guide](https://developers.tiktok.com/doc/content-posting-api-media-transfer-guide) | None (spec matches). |
| Tokens: access 2 hours (`expires_in`), refresh 180 days (`refresh_expires_in`), and a refresh "will return a different `refresh_token`". | [Official] [token management](https://developers.tiktok.com/doc/oauth-user-access-token-management) | Confirms the rotating-token design (per-account lock, persist before release). |

## 4. Agent interface (MCP)

| Fact | Evidence | Spec change |
| --- | --- | --- |
| Current MCP revision is **2026-07-28**. It is stateless: no `initialize` handshake, no `Mcp-Session-Id`. Each request carries its protocol version in `_meta` (and `MCP-Protocol-Version` on Streamable HTTP). `server/discover` is mandatory for servers. Tasks became an extension. Roots, Sampling and Logging are deprecated. Authorization hardened: RFC 9207 `iss` validation, `application_type` in dynamic registration, credentials bound to their issuer. | [Official] [versioning](https://modelcontextprotocol.io/specification/versioning); [Community] summaries of the changelog | Spec 06 §7: build the local stdio server on the official Python SDK at a version that serves both 2025-11-25 and 2026-07-28. Use no deprecated features (no sampling, roots or logging). Hosted HTTP transport stays deferred until the hosted phase, and is built against 2026-07-28 then. |
