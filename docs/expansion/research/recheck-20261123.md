# Re-check of platform facts, 2026-11-23

Third pass, one day after `recheck-20261122.md`, run before the publishers and the connect runbook
were built. Same evidence labels. Each item says what changes in the specs or the build.

## 1. Instagram API with Unified Login exists and is documented

| Fact | Evidence | Change |
| --- | --- | --- |
| Meta's content-publishing page now has three columns: **Instagram API with Unified Login**, Instagram API with Instagram Login, Instagram API with Facebook Login. Unified Login uses Facebook Login for Business, hosts `graph.facebook.com` and `rupload.facebook.com` (resumable video upload), permissions `instagram_basic` + `instagram_content_publish`, and a **Business Integration System User access token**. | [Official] [content publishing](https://developers.facebook.com/docs/instagram-platform/content-publishing), read 2026-11-23 | Reverses recheck-20261122 §2 ("Unified Login as a name was not found"). Spec 08 §3: the second Instagram adapter is `instagram_unified` (Unified Login), not a generic "Facebook Login for Business" adapter. |
| Setup: a Meta app with the **Manage messaging & content on Instagram** use case, **owned by a business portfolio**, using Facebook Login for Business; an HTTPS redirect URL; an HTTPS webhook endpoint; an Instagram professional account (test users not supported). The App Dashboard tab is **Use cases > Manage messaging & content on Instagram > Customize > API setup with Unified login**. | [Official] [get started](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started) | Owner step in `docs/CONNECT_ACCOUNTS.md`: a (free) business portfolio is needed for this path. Business *verification* is not needed for Standard Access. |
| Login: `https://www.facebook.com/dialog/oauth?client_id=<META_APP_ID>&config_id=<CONFIG_ID>&redirect_uri=<HTTPS>&response_type=code` (`display=popup`, `prompt=login` optional). `config_id` is not a secret. Exchange: `GET https://graph.facebook.com/v27.0/oauth/access_token?client_id&client_secret&code` with the **Meta** app id/secret (not the Instagram app id/secret). | [Official] get started, [authentication](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication) | Adapter settings: `instagram_unified_config_id` (non-secret), Meta app id/secret (secrets). No scope list in the URL: permissions come from the configuration. |
| The token belongs to the client's business portfolio, not the person; it keeps working if that person leaves. Expiry is chosen per configuration (shown in the configuration preview) and managed with the **Business Integration System User Access Token Management API**, which needs `business_management` and the client business id. It stops working if the app is removed from the portfolio or the IG account moves portfolio: then stop retrying and ask to reconnect. Store tokens in a variable-length column with the client business id, IG account ids and `config_id`. | [Official] authentication | Token record gains `client_business_id`, `config_id`; refresh scheduling only when the configuration's expiry is finite. Failure → `needs_reauth`, never a retry loop. |
| `/me` is the system user. Get `GET /me?fields=client_business_id` and `GET /me/assigned_instagram_accounts?fields=id,username` (one token may cover several IG accounts). All calls use the IG account id in the path. | [Official] get started | Connect flow lists the assigned accounts and connects the one the owner picks (refuse a mismatch with an already-connected account). |
| Permission mapping from Instagram Login: `instagram_business_basic`→`instagram_basic`, `instagram_business_content_publish`→`instagram_content_publish`, `..._manage_comments`→`instagram_manage_comments`, `..._manage_insights`→`instagram_manage_insights`, `..._manage_messages`→`instagram_manage_messages`. Standard Access on saving the configuration (people with a role on the app); Advanced Access via App Review + Live mode for others. | [Official] [permissions](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/permissions) | Capability function maps both scope families. |
| Resumable upload: create the container with `upload_type=resumable` on `graph.facebook.com`, then `POST https://rupload.facebook.com/ig-api-upload/<CONTAINER_ID>` with the file from disk; then poll `status_code` and `media_publish` as usual. | [Official] content publishing | With `instagram_unified`, Reels and videos publish **from local disk with no public URL and no R2 bucket**. Images still need a public `image_url` (resumable is for video). |

**Recommendation for the owner:** Unified Login is now the better path for a local install that
publishes Reels, because it removes the R2 requirement for video. It costs one extra owner step (a
free Meta business portfolio owning the app). The Instagram Login adapter stays supported.

## 2. Metric definition changes (invariant 6)

| Fact | Evidence | Change |
| --- | --- | --- |
| From **2026-11-16** YouTube public `viewCount` (channels, videos, `videos.batchGetStats`) includes **co-views** (several people watching on one TV). From 2026-08-27 a view counts from the first frame. | [Official] [revision history](https://developers.google.com/youtube/v3/revision_history), read 2026-11-23 | YouTube `views` metric definition records the definition version by date; charts that span 2026-11-16 mark the change; no comparison across it without the marker. |
| Instagram `total_like_count`, `total_comments_count`, `total_views_count` (and insights `total_*`) **aggregate Instagram, Facebook crossposts and boosted media** (2026-04-22). | [Official] [IG changelog](https://developers.facebook.com/documentation/instagram-platform/changelog) | Never store a `total_*` value as an Instagram metric; if collected it is a separate, labelled cross-surface metric. |
| From 2026-07-30 `media_url` is omitted for videos with copyrighted/licensed audio (even for the owner's own media); the response is still 200. | [Official] IG changelog | Sync parser treats `media_url` as optional and falls back to `thumbnail_url`/`permalink`. |
| `is_ai_generated` added 2026-06-22 for both Facebook Login and Instagram Login; carousel parent only. | [Official] IG changelog | Already in spec 08 §3. |

## 3. Unchanged since 2026-11-22

- YouTube quota: separate buckets for `videos.insert`, `search.list` (2026-06-01) and
  `videos.batchGetStats` (1 unit, own 10,000/day bucket, 2026-06-03); upload ≈100 units
  (2025-12-04). Already in `research/youtube.md` §1. Sync should prefer `videos.batchGetStats`
  for statistics so the shared bucket is kept for everything else.
- TikTok inbox upload reference still "Last updated August 4, 2026": `video.upload`, 6 requests per
  minute per token, `FILE_UPLOAD` or `PULL_FROM_URL` (verified URL prefix).
- Meta data-deletion callback: HTTPS POST with `signed_request` (`<base64url sig>.<base64url
  payload>`, HMAC-SHA256 over the payload with the app secret, payload `algorithm` = `HMAC-SHA256`,
  `user_id` = app-scoped id); respond `{ url, confirmation_code }` pointing at a human-readable
  status page. [Official] [data deletion callback](https://developers.facebook.com/docs/development/create-an-app/app-dashboard/data-deletion-callback).
- MCP Python SDK newest is 2.3.0 (depends on `mcp-types==2.3.0` and `httpx2`); the agent build
  pins the newest release at least 14 days old that serves 2025-11-25 and 2026-07-28.
